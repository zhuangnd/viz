# 1. 设计目标与原则

## 1.1 一句话定位

> **一个能"看见行程"的规划工具** —— 不是旅游宣传页，而是一张可交互的日本旅行地图 + 行程时间轴 + 预算算盘。

## 1.2 目标用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 首次赴日者，行前规划 | 桌面浏览器，2–5 次深度访问 | 搞懂"该去哪、怎么走、要花多少" |
| 行中查阅 | 手机，随时掏出 | 快速看"今天去哪、怎么去" |
| 决策阶段 | 反复切换季节/路线对比 | 比较不同方案的成本与可行性 |

## 1.3 设计原则（5 条）

| 原则 | 具体含义 |
|---|---|
| **① 信息密度优先** | 首屏即展示路线全貌与核心预算，不做营销式大图 |
| **② 地图是主角，不是装饰** | 地图占首屏 ≥50% 高度，承载全部 POI 与路线 |
| **③ 可计算** | 预算、里程、时间不写死"参考值"，由用户输入实时计算 |
| **④ 诚实标注不确定项** | 票价/班次标注"核验日期"，冬季风险显式警告 |
| **⑤ 零构建优先** | 单文件可打开，无 npm、无构建、无 CDN 依赖，离线可用 |

## 1.4 明确不做的事

- ❌ 不做登录/注册/后端（纯静态，localStorage 存进度）
- ❌ 不引入前端框架与打包工具（用原生 JS + ES Module 单文件）
- ❌ 不做在线订票/下单（跳出到官方站点）
- ❌ 不使用收费地图 API（用自绘 SVG + 开放地理数据）

# 3. 核心功能模块

## 3.1 F1 决策器（Decision Widget）

**位置**：顶栏常驻 + 首屏 Hero 区

**交互**：

| 控件 | 类型 | 联动效果 |
|---|---|---|
| 季节 | 三段 Tab（1–2月 / 9月下–10月上 / 11–12月） | ① 地图上标注红叶时点带 ② 预算中住宿系数变化 ③ 显示对应风险提示卡（冬季大雪 / 台风 / 人流） |
| 预算档位 | 双段切换（经济 / 舒适） | 全站住宿、餐饮价格即时替换；预算表重算 |
| 人数 | 下拉（单人 / 双人 / 双人+1娃 / 家庭） | 交通、门票、住宿总价重算；儿童价自动应用 |
| 出行天数 | 滑块（15–20） | 行程框架按比例伸缩；预算按天数线性外推 |

**关键设计**：季节与预算不是"装饰性筛选"，而是**真正驱动全站数据变化的主控变量**。

## 3.2 F2 路线对比矩阵

**功能**：8 条路线（5 经典 + 3 村上）以卡片矩阵呈现，支持按维度排序/筛选。

| 维度 | 说明 |
|---|---|
| 主题 | 庭园/工艺/自然/艺术/文学/温泉 |
| 覆盖区域 | 关西/东京/濑户内/北陆/九州/四国 |
| 建议天数 | 3–6 日 |
| 季节适配 | ★ 评分（1–2月 / 9–10月 / 11–12月 各自打分） |
| 人流密度 | 极低 / 低 / 中 / 高 |
| 预算档适配 | 经济 ✓ / 舒适 ✓ |
| 是否需预约 | 是（具体场馆）/ 否 |
| 是否含村上元素 | 是 / 否 |

**交互**：点击任一路线 → 地图自动缩放到该路线区域，右侧展开逐日行程；可"加入我的行程"加入行程池。

## 3.3 F3 行程编排器（Itinerary Builder）

**功能**：从 8 条路线中挑选片段，拼接成自己的 15–20 日行程。

```
[起点: 厦门] → 抵达 → [路线片段 A: 京都庭园 4日] → [移动] → [片段 B: 东京工艺 4日] → ... → 返程
```

**交互**：
- 拖拽排序（HTML5 Drag & Drop）
- 自动计算**总天数、总里程（估算）、总预算**
- 自动检查冲突：❌ 时间重叠、⚠️ 连续换酒店 ≥3 次、⚠️ 单日移动 >3 小时
- 一键导出为 Markdown / 打印为 PDF（浏览器打印样式）

## 3.4 F4 预算计算器

**实时公式**（全部可展开查看）：

```js
总预算 = 往返机票
       + (住宿单价 × 晚数 × 季节系数 × 人数修正)
       + 境内交通（按所选路线逐段累加 + Pass 选项对比）
       + 餐饮(基础日均 × 天数 × 档位系数)
       + 门票(选中 POI 的票价累加)
       + 杂项(保险 + eSIM + 宅急便 + 签证费)
```

**关键交互**：
- **JR Pass vs 单程票实时对比**：选中长距离段（如东京–博多）后，自动并列显示两种方案总价并给出建议
- **季节系数表**（透明展示，让用户知道数字从哪来）：

| 季节 | 住宿系数 | 机票系数 | 说明 |
|---|---|---|---|
| 1–2 月中下旬 | ×0.65 | ×0.85 | 全年最低 |
| 9 月上旬 | ×0.80 | ×1.00 | 平季 |
| 9 月下旬–10 月上旬 | ×1.00 | ×1.10 | 开始上涨 |
| 11 月下旬–12 月上旬 | ×1.45 | ×1.40 | 红叶旺季 |
| 樱花季 3 月底–4 月初 | ×1.30 | ×1.50 | — |

## 3.5 F5 签证与清单工具

- **签证进度看板**：材料清单 10 项可勾选，自动计算"还需 X 天才能递交"
- **办理时间轴**：可视化 T-60 → T-1 的倒计时节点
- **费用明细**：使馆费（715/1430）+ 代办费区间，明确标注"以 2026-07-01 起官方口径"

## 3.6 F6 防坑清单

12 个坑做成卡片，翻开显示"后果/正确做法"。支持"已避坑"标记，localStorage 持久化。

# 4. 地图可视化方案

## 4.1 技术选型：不使用在线地图 SDK

| 方案 | 结论 |
|---|---|
| Google Maps JS API | ❌ 需 API Key、有配额、对中国大陆用户常不可达 |
| Mapbox GL | ❌ 需 Token、离线不可用 |
| Leaflet + OpenStreetMap 瓦片 | ⚠️ 需联网瓦片，离线失效；国内访问 OSM 慢 |
| **自绘 SVG + 内置地理数据** | ✅ **选定**：零依赖、离线可用、风格完全可控、响应式天然 |

> 这是"零构建"约束下的最优解。地图不是用来导航的，是用来**看空间关系**的——自绘 SVG 完全够用。

## 4.2 地图渲染架构

```
数据层：内嵌 GeoJSON 简化版（海岸线轮廓 + 都道府县边界 + 城市点）
     ↓
投影层：Mercator 投影 → viewBox 坐标变换
     ↓
渲染层：SVG <path>（陆地） + <circle>（城市） + <polyline>（路线） + <g>（POI 标记）
     ↓
交互层：viewBox 变换实现平移缩放 + 标记点 hover/click 事件
```

## 4.3 地理数据（内嵌，简化）

| 图层 | 数据 | 精度 |
|---|---|---|
| **日本轮廓** | 简化多边形（约 80–120 点） | 足以辨识轮廓 |
| **都道府县界** | 主要县界简线 | 辅助定位 |
| **城市点** | 约 40 个主要城市（含本文所有目的地） | 精确经纬度 |
| **POI 点** | 约 90 个景点/场馆/车站 | 精确经纬度 |
| **铁路线（示意）** | 东海道/山阳/九州/中央等主干 | 示意，非精确线位 |

> 坐标统一使用 WGS84 经纬度（约小数点后 4 位，精度约 11 米），完全满足旅行规划需求。

## 4.4 地图交互设计

| 交互 | 行为 |
|---|---|
| **点击城市/POI** | 右侧滑出详情卡：名称、门票、开放时间、预约要求、休馆日、交通、所属路线 |
| **悬停路线** | 路线加粗 + 沿途城市高亮 + 浮层显示该段交通方式/时长/票价 |
| **缩放** | 滚轮/双指缩放，级别 0（全国）→ 1（区域）→ 2（城市） |
| **平移** | 拖拽移动，边界阻尼 |
| **"飞往"某地** | 点击行程某天，地图平滑动画平移到当日区域并高亮当日 POI |
| **图层开关** | 经典路线 / 村上路线 / 自然 / 文化 / 温泉 分类过滤 |
| **重置** | 一键回到全国视图 |

## 4.5 地图上的信息叠加层

| 叠加 | 说明 |
|---|---|
| **季节色带** | 切到 11–12 月时，地图叠加红叶进度色带（北早南晚），直观解释"为什么 10 月看不到京都红叶" |
| **冬季风险带** | 切到 1–2 月时，日本海侧叠加"大雪高风险"色带（2026 年实测：新潟 100cm/24h、札幌 65cm/48h） |
| **人流量热区** | 按季节显示不同拥挤度（1–2 月极低、10 月中后高） |

> 这三个叠加层是本项目**最有信息价值的设计**——它们把"为什么"直接画在地图上，而非文字描述。

# 5. 路线示意规划

## 5.1 路线几何生成

每条路线由有序的城市/站点序列定义，地图上自动生成为**平滑曲线**（Catmull-Rom 样条）而非折线：

```js
// 示意算法（非精确路径，仅表达空间关系）
routePath(cities) =>
  cities.map(c => [lng2x(c.lng), lat2y(c.lat)])
         → catmullRomSpline(closed=false, tension=0.5)
         → "M x0,y0 Q ... " SVG path d
```

**为什么用样条曲线**：折线看起来像"硬折返"，样条更接近真实交通走廊的弧度，视觉更自然。

## 5.2 行程条（Route Strip）

地图下方配一条**水平行程条**，按天数比例展示：

```
D1  D2  D3  D4  D5  D6  D7  D8  D9  D10 ... D18
▓▓  ▓▓  ▓▓  ▓▓  ▓▓  ▓▓  ▓░  ░░  ░░  ░
[移动]  [ 京都庭园 ]  [移动] [濑户内  ]  [东京]  [返程]
```

- 每个色块 = 一段活动；宽度 = 占用天数
- 灰色窄块 = 交通移动日（视觉上明显"空"）
- 点击色块 → 地图飞至对应区域 + 展开当日详情
- 底部标注**移动日占比**（如"18 日中有 5 日在移动 = 28%"），直观提示行程是否过于紧凑

## 5.3 路线示意表（每条路线的固定结构）

```
路线头部：名称 / 主题 / 建议天数 / 季节适配 / 人流 / 预约要求
  ↓
路线地图：小图（仅该路线区域，自动缩放）
  ↓
逐日时间轴：Day-by-Day 卡片
  每张卡包含：
    · 当日主题
    · 时间轴（几点到几点做什么）
    · 交通段（方式 + 时长 + 票价）
    · 食（推荐 + 预算）
    · 住（区域 + 预算）
    · 当日预算小计
  ↓
路线总预算：住宿/交通/餐饮/门票/杂项 拆解
  ↓
注意事项：⚠️ 预约要求 / 🚨 季节风险 / 💡 省钱技巧
```

# 6. 交互设计

## 6.1 交互原则

| 原则 | 说明 |
|---|---|
| **即时反馈** | 任何输入变化 <100ms 产生视觉响应 |
| **可逆** | 所有筛选/切换可一键还原，不设死路 |
| **可解释** | 计算结果可展开看公式与系数来源 |
| **不丢失上下文** | 切 Tab 不重置滚动位置与筛选状态 |
| **移动端优先触控** | 触控目标 ≥44×44px |

## 6.2 关键交互清单

### 决策流
```
进入 → 顶栏选择季节（默认 9月下旬–10月上旬）→ 选择预算档位（默认经济）
     → 选择人数（默认单人）→ 首屏地图已按此参数渲染推荐路线
     → 点击"看看推荐路线" → 地图高亮当前条件下最优的 2–3 条
```

### 探索流
```
路线对比矩阵 → 点击某路线 → 地图动画飞至该区域 → 右侧展开行程
   → 点击某一天 → 时间轴滚动到该天 → 地图聚焦当日 POI
   → 点击"加入我的行程" → 行程池更新 → 预算重算
```

### 行中查阅（移动端）
```
底部 Tab Bar：地图 / 行程 / 预算 / 清单
点"行程" → 今天是 D? → 默认显示当日（按出发日推算）→ 一键高亮地图
```

## 6.3 状态管理

| 状态 | 存储方式 | 说明 |
|---|---|---|
| 季节/档位/人数 | localStorage | 刷新保留 |
| 我的行程 | localStorage | 行程片段序列 |
| 已勾选清单项 | localStorage | 签证清单/出发清单/避坑 |
| 出发日期 | localStorage + URL param | 用于计算"今天是 D?" |
| URL 状态 | query string | 季节/路线/天 可分享链接 |

> **URL 可分享**是重要设计：用户可以把"我选的 9 月 + 经济 + 路线 A"以链接形式发给同行者。

## 6.4 动效规范

| 场景 | 动效 | 时长/缓动 |
|---|---|---|
| 地图飞往某地 | viewBox 插值平移 + 缩放 | 800ms / cubic-bezier(0.4, 0, 0.2, 1) |
| Tab 切换 | 内容淡入 + 8px 上移 | 200ms ease-out |
| 预算数字变化 | 数字滚动（requestAnimationFrame） | 400ms |
| POI 详情卡 | 右侧滑入 | 300ms |
| 路线高亮 | stroke-width 过渡 | 200ms |
| 移动端筛选面板 | 底部抽屉上滑 | 250ms |

> 尊重 `prefers-reduced-motion`：开启时关闭所有动效，仅瞬时切换。

## 6.5 无障碍

- 所有交互元素可键盘 Tab 聚焦，`:focus-visible` 有明显轮廓
- 地图提供文字替代列表（路线表格），屏幕阅读器可读
- 对比度 ≥ 4.5:1（正文）；色带信息同时配文字标注，不只靠颜色传达
- ARIA 标注：`role="tab"` / `aria-selected` / `role="dialog"`

# 7. 视觉设计系统

## 7.1 风格定位

> **"和纸与墨"**：日本传统美学的当代表达 —— 大量留白、克制的用色、细线条、衬线标题。

**避免**：霓虹渐变、大圆角卡片堆砌、Emoji 图标轰炸、千篇一律的 Material 风格。

## 7.2 色彩系统

```css
/* 基础色 —— 浅色主题 */

--sumi-light: #6B665C;   /* 淡墨（次要文字） */
--washi:      #FFFFFF;   /* 卡片白 */

/* 主色 —— 朱砂红（点缀，不大面积） */
--shu:        #C1362F;

/* 功能色 */

--gold:       #B8912F;   /* 金（村上/文学路线） */

/* 季节主题色（Tab 切换时全站微调） */

--season-autumn: #C1712F;   /* 橙红 */
```

## 7.4 字体

```css
--font-serif: "Songti SC", "Noto Serif SC", "Source Han Serif SC", serif;  /* 标题 */
--font-sans:  -apple-system, "PingFang SC", "Hiragino Sans GB", sans-serif; /* 正文 */
--font-mono:  "SF Mono", monospace;  /* 数字/票价 */
```

- 标题用衬线（和纸质感），正文用系统无衬线（可读性）
- **数字全部用等宽**，避免预算表格跳动

## 7.5 间距与栅格

- 基础间距单位 4px，序列 4/8/12/16/24/32/48/64
- 桌面端 12 栏栅格，最大内容宽 1440px
- 卡片圆角 **小**（4–6px），日本美学不喜大圆角
- 边框用 1px 实线 + 极淡阴影，避免悬浮感

## 7.6 空状态与加载

- 空状态：用和纸纹理底 + 一句引导文案 + 一个 CTA
- 数据加载：骨架屏（不用 spinner）

# 8. 响应式策略

## 8.1 断点定义

| 断点 | 宽度 | 设备 | 布局 |
|---|---|---|---|
| **XL** | ≥1440px | 大屏桌面 | 三栏：导航 + 地图/内容 + 侧栏 |
| **L** | 1024–1439px | 笔记本 | 两栏：导航（可收起）+ 内容 |
| **M** | 768–1023px | 平板 | 两栏竖排：地图在上，内容在下 |
| **S** | 375–767px | 手机 | 单栏 + 底部 Tab Bar |
| **XS** | <375px | 小屏手机 | 单栏，紧凑间距 |

## 8.2 各断点差异化设计

### 桌面（≥1024px）
- 左侧导航固定 280px，可滚动
- 地图与详情卡左右分屏
- 预算表完整展开显示

### 平板（768–1023px）
- 导航收为抽屉（汉堡菜单）
- 地图高度降至 420px
- 详情卡改为覆盖在地图上的浮层

### 手机（<768px）
- **底部固定 Tab Bar**（地图/行程/预算/清单）56px 高
- 地图占满上部（约 45vh），可下拉收起为小地图条
- 行程时间轴改为**单列卡片流**
- 预算表转为**分项折叠 + 底部汇总条**
- 路线对比矩阵从表格改为**横向滑动卡片**

### 触控适配
- 地图支持双指缩放与单指平移（`touch-action: none` 仅作用于地图容器，避免影响页面滚动）
- 所有可点击目标 ≥44×44px
- 筛选器用底部抽屉而非下拉（更好点按）

## 8.3 打印样式

为"导出日程"提供 `@media print`：
- 隐藏导航、按钮、交互控件
- 时间轴转为黑白清晰的排版
- 地图 SVG 转为静态图片
- 分页控制：每个 Day 不跨页

# 9. 技术选型与数据模型

## 9.1 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 结构 | 原生 HTML5 语义标签 | 无框架依赖 |
| 样式 | 单文件内嵌 CSS + CSS 变量 | 便于主题切换与响应式 |
| 脚本 | 原生 ES Module + 状态机 | 零依赖，浏览器直接跑 |
| 地图 | **自绘 SVG** | 离线、风格可控 |
| 数据 | JSON 内嵌于 `<script type="application/json">` | 单文件、易维护 |
| 存储 | localStorage | 免后端 |
| 字体 | 系统字体栈 | 免网络请求 |

**明确不使用**：React/Vue、npm、打包器、Tailwind CDN、图表库。

## 9.2 数据模型

```js
// ===== 地理 =====
GeoCity   = { id, name, nameJa, lng, lat, region, isPort, shinkansenStop }
GeoPOI    = { id, name, lng, lat, cityId, category, ticket, openHours,
              closedDays, reservationRequired, note }

// ===== 路线 =====
Route     = { id, name, theme, type: 'classic'|'murakami',
              days, seasons: { winter: 1-5, autumn: 1-5, maple: 1-5 },
              crowdLevel, needsReservation, budgetHint,
              cities: [cityId...], pois: [poiId...],
              dayPlan: [ { day, title, items: [...],
                           transport: {...}, meal: {...},
                           stay: {...}, estCost } ],
              warnings: [ { level: 'warn'|'danger'|'tip', text } ] }

// ===== 交通 =====
TransportLeg = { from, to, mode: 'shinkansen'|'train'|'bus'|'ferry'|'walk',
                 durationMin, costJPY, note }

// ===== 预算 =====
BudgetModel  = { basePriceJPY: { flight, hotelPerNight, foodPerDay, misc },
                 seasonFactor: { winter: 0.65, autumn: 1.0, maple: 1.45 },
                 tierFactor: { economy: 1.0, comfort: 1.8 },
                 childFactor: 0.5 }

// ===== 季节数据 =====
SeasonData = { id, label, foliage: [{ region, peakStart, peakEnd }],
               snowRisk: [{ region, level, note }],
               crowdLevel, priceIndex }
```
