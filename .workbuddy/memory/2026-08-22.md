## viz_as_language · 总结辨析 + 可视化网页

- **总结**：`docs/` 下三篇 AI 文档（ChatGPT/Gemini/Claude）共同回答「数据可视化为何未能成为大众文本」。共同结论：可视化是数量关系的专用语言而非通用媒介。分歧点集中在「门槛 vs 局限性何者更根本」。
- **补充辨析**：
  1. 门槛与局限同源（Claude 的二分法可磨/不可磨有分析力，但二者实为同一原因的两面）
  2. 文字在简化，可视化在复杂化（符号集演化的关键差异，未被三篇覆盖）
  3. 寄生性是程度问题而非有/无
  4. 设计能消解社会门槛，不能消解结构性局限
  5. AI 改变三层：生产端塌陷、阅读端降低、量化环节是变数
- **产出物**：
  - md: `viz_as_language/docs/门槛与局限-总结与辨析.md`（含共同结论、对比表、论证脉络手风琴、五维辨析、综合结论、附录概念表）
  - html: `viz_as_language/index.html`（单文件、零依赖、含 7 个交互模块：四表达方式 tab/双重门槛动画/信息边界翻牌/嵌套圆/演化趋势+时间线/寄生性注释开关/AI 管线切换）

## 技术备忘

- 单文件 HTML 内联 CSS/JS，无外部依赖；色板用 CSS 变量统一（文字=橙、图像=蓝、可视化=紫、AI=绿、局限=红）
- SVG 几何属性（r/cy）动画在 Chrome/Safari 现代版本中可通过 CSS transition 触发
- 侧边导航 + 滚动进度条 + IntersectionObserver 触发进入动画
- 验证方式：python -m http.server 启动 → agent-browser open → screenshot 各交互态

## viz_as_language · 卡片式可视化页面（第二轮迭代）

- **需求**：在已有 `index.html`（长滚动编辑型）之外，新增一个静态卡片式页面 `cards.html`。结构保持 md 不变（三篇文档总结 → 补充辨析 → 综合结论 + 附录），内容进一步提炼为 15 张知识卡片，每张可导出为 PNG。
- **设计决策**：
  - 布局：CSS `column-count` 实现 masonry 瀑布流（桌面 3 列 / 平板 2 列 / 移动 1 列）
  - 内容：每张卡片 = 编号 + 标签 + 标题 + 精炼正文 + 关键观点框（带色左边框）+ 微型可视化
  - 配色按章节分组：总结=紫(#6D28D9) / 辨析=橙(#C2410C) / 结论=绿(#047857) / 附录=灰(#78716C)
  - 微型可视化：SVG（汇聚箭头/嵌套圆/散点对比/分隔符）或 CSS（流程链/表格/渐变条/分层堆/概念网格）
  - 导出：html2canvas 1.4.1 via CDN，2x scale，onclone 隐藏按钮，白色背景
- **关键实现**：
  - Hero 卡片用深色背景（#1C1C28）独立于 masonry 之外，区分"核心问题"和"知识卡片"
  - IntersectionObserver 触发卡片淡入；导出前强制 `.in` 避免截到不可见卡片
  - onclone callback 隐藏所有 `.card-export` 按钮避免出现在导出图
  - 文件命名：`{id}_{title}.png`（如 `01_三家殊途同归.png`）
  - 整体约 18KB 单文件，仅 html2canvas 一个外部依赖
- **验证结果**：Hero/总结 7 张/辨析 5 张/结论 2 张 全部渲染正确；单卡导出 1360×592px@2x≈148KB；全部 15 张导出完成无控制台错误
- **产出**：`viz_as_language/cards.html`（不修改原 `index.html`）
- **协作模式**：用户偏好"先重述需求 → 确认 → 执行"的两步走模式；第二轮迭代在第一轮基础上做形式转换而非内容新增
