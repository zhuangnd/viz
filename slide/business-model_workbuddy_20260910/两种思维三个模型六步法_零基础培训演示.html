两种思维

结构化思维
把含糊的问题拆开看、说清楚
解决：如何看清问题
动作：分解 · 分类 · 构建逻辑关系 · 可表达
工程化思维
把想法变成能落地、能验证的步骤
解决：如何改变现实
特征：可定义 · 模块化 · 可验证 · 迭代
一句话记住：结构化思维让你"看懂题"，工程化思维让你"做对题"。

拆解
结构化思维 → 问题模型
业务原话：
"今年出口贸易增长乏力，得查查怎么回事。"
——带情绪、有方向、没动作。

三个拆解动作

问什么答案为什么重要
跟谁比？去年同期 / 全国均值 / 兄弟关没有基准，"乏力"站不住
乏力在哪？国家、HS 大类、企业主体、贸易方式不拆维度，原地打转
为什么乏力？量？价？结构变了？拆因才能拆方案

拼成公式（问题模型）

出口贸易额 = Σ 各 HS 编码 × 单价 × 数量 同比增长率 = (本期贸易额 − 同期贸易额) ÷ 同期贸易额 乏力归因 = 量贡献 + 价贡献 + 结构贡献
💡 教学要点
这一步不进工具，白纸写就行。拆到"能落到一张表的一个字段"为止。

找数
结构化 → 工程化 → 信息模型

把公式里的变量翻译成"数据在哪儿"

公式变量数据落在哪口径坑
贸易额报关单 × 总价（美元）含运保费吗？
数量报关单 × 数量 + 法定单位散货/整柜怎么折？
HS 编码报关单 × 商品编码拆到 4 位还是 8 位？
同期数据历史归档表编码版本换过没？

信息模型：表关系图

[报关单主表]──┬──[商品归类表] (HS编码 → 大类名) ├──[企业备案表] (经营单位代码 → 企业名) ├──[国别代码表] (目的国 → 区域) └──[历史归档表] (按月分区, 上年同期)

每个节点 = 一段 SQL 代码，你只是没看见它。
工具会自动拼成 SELECT-WHERE-GROUP BY-ORDER BY。
拖出来的不是一张漂亮的图，是一份能跑、能改、能复用的 SQL 脚本。

等价 SQL 代码

WITH base AS ( SELECT hs4, SUM(CASE WHEN year=2026 THEN total_price_usd END) AS v_c, SUM(CASE WHEN year=2025 THEN total_price_usd END) AS v_y FROM customs_declaration WHERE ie_flag = 'E' AND year IN (2025, 2026) GROUP BY hs4 ) SELECT *, ROUND((v_c - v_y) / NULLIF(v_y, 0) * 100, 2) AS yoy_pct FROM base WHERE v_y > 1000000 ORDER BY yoy_pct ASC LIMIT 50;

验证
工程化思维 · 可验证
不要先激动。跑出来一堆数，先别急着解读，先验。

四个验证动作

  • ✓
    行数核对 — 跟总署下发的贸易统计月报对总数
    标准：工具数 = 月报数
  • ✓
    空值检查 — 查 HS 编码为空的报关单占比
    标准：＜ 0.5% 才放心
  • ✓
    极值检查 — 单笔 ＞ 1 亿美元 / ＜ 100 美元的列出来
    标准：确认不是录错
  • ✓
    抽样回溯 — 随机抽 100 条回 H2010 报关单回执系统比对
    标准：字段、金额、HS 三件套一致
❌ 最常犯的错
"SQL 跑出来了，同比增长 -3.6%，报告。"
正确做法：先验行数对了、空值可控、极值没离谱、抽样能对上——才能用 -3.6% 这个数。
"模型说有疑点，业务说没有，通常不是业务错了。"
可验证是工程化思维最容易被忽略、但最值钱的一格。

分析
工程化 → 结构化 → 表 + 图 + 三句话

产出三件套：一张表 + 一张图 + 三句话

每张表、每张图背后都要配三句话——这三句话本身又是一次"结构化拆解"。

空间拆

"下滑 60% 集中在机电产品，前 3 个 HS 大类贡献了 8 成。"

因果拆

"量贡献 -2.1pp、价贡献 -1.5pp——量价齐跌是主因。"

主体拆

"中小企业下滑 -15%，头部企业 +6%，集中度在上升。"

SQL 跑得动是工程化，能讲清楚为什么下滑则是结构化思维的事。

报告
结构化思维 · 回译闭环

汇报三步法

把工程化的产物翻译回业务话。

第一步 · 拆解
"增长乏力，拆开看，主要来自三个维度：
按 HS 大类分，机电产品占出口 60%，今年前八月同比 -4.2%，是主力拖累；
按国别分，对东盟 +12%，对欧美 -8%，结构在悄悄切换；
按企业分，中小企业下滑 -15%，头部企业反而 +6%。"
第二步 · 模型
"用贸易额 = 量 × 价 × 结构一拆：
量贡献 -2.1pp、价贡献 -1.5pp、结构贡献 +0.4pp。
翻译成业务话——量价齐跌是主因，结构升级是亮点。"
第三步 · 方案
"建议下一步分三条线核实：
① 查机电产品前十大 HS 编码的量价明细，看是订单转移还是价格战；
② 拉头部企业新增客户清单，看集中度上升是产业升级还是订单聚集；
③ 抽样 5 家中小出口企业，了解是资金压力还是汇率/关税问题。"

报告里不要出现这些词

不要说应该替换为
"我用了结构化思维""我们把问题拆成三块来看"
"我用 SQL 跑了一下""我们拉了一下数据"
"yoy_pct 是 -3.6%""今年前八月同比下滑 3.6%"
"JOIN 了 6 张表""把企业、HS、国别几方面都纳入了分析"
业务点头了，6 步才算闭环。
只会念节点名，翻译链就是断的——拖出来的不是答案，是半成品。
模块 4 · 学员练习

现在轮到你了

"昨天通关数据好像有点异常，看看发生了什么。"

用六步法，快速走一遍。

  • ①
    拆解 — "异常"跟谁比？哪个维度异常？量还是价？→ 在白纸上拼出公式
  • ②
    找数 — 昨天的报关单在哪张表？字段口径是什么？→ 画出表关系
  • ③
    建模 — 拖出节点链：数据源→过滤(昨天)→聚合→计算(偏差)→排序
  • ④
    验证 — 行数对不对？空值多少？有没有极端值？
  • ⑤
    分析 — 哪个品类/企业/国别偏差最大？→ 写三句话
  • ⑥
    报告 — 用汇报三步法讲出来
⏱
建议用时：20 分钟
讲师不演示，只纠偏。六步法的价值不在于"看懂了"，在于"自己做了一遍"。
模块 5

避坑清单

零基础最常踩的五个坑。

❌ 跳过拆解，直接进工具拖节点
✅ 白纸写不出公式就别碰工具
❌ 口径没对齐就开始聚合
✅ 先只拖"数据源"节点，确认字段含义
❌ 跳过验证直接给结论
✅ 强制挂上四个验证节点
❌ 图很漂亮但结论说不清
✅ 每张图强制配三句话（空间/因果/主体）
❌ 报告里堆 SQL 术语
✅ 自查：不许出现 SELECT / WHERE / JOIN / GROUP BY

回译检验三问

❶

能用一句业务话讲清六步分别做什么？

❷

能把任何一句业务话拆成一个公式？

❸

能在白板上画出汇报一页纸？

三个都能 → 你就不是零基础了。
