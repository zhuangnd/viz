# 课件逻辑梳理：面向零基础 SQL 学员

## 一、整体设计思路

**一条主线**：用两种思维、三个模型工具，走通"业务问题 → 数据结论"的六步路。

**两个贯穿案例**：
- **出口乏力**：作为"慢案例"，从头到尾走完全流程，让学员看见每一步长什么样。
- **昨天发生了什么**：作为"快案例"，在讲完六步后快速复用，检验学员能不能迁移。

**核心主张**（课件第一页就该亮出来的）：

> SQL 不是最难的部分，想清楚才是。

---

## 二、课件结构（建议 7 个模块）

### 模块 0：开场 —— 为什么是你，不是 AI

**目的**：解决"为什么要学"的动机问题，引出五懂一具备。

**逻辑线**：
1. 抛一个问题："如果 AI 能写 SQL，你为什么还要学？"
2. 给出答案：**AI 写得了代码，判不了对错。** 用讲稿里"AI 编文号"的真实故事——文号、日期、原文一应俱全，全是现场编的。
3. 引出能力标尺：**五懂一具备**

| 懂什么 | 一句话 | 在六步法里的位置 |
|---|---|---|
| 懂业务 | 知道问题从哪来 | 步骤 1 拆解的底气 |
| 懂系统 | 知道数据在哪 | 步骤 2 找数的地图 |
| 懂技术 | 能把数据弄出来 | 步骤 3 建模的手艺 |
| 懂数据 | 知道口径的坑 | 步骤 4 验证的敏感 |
| 懂分析 | 把数字变成判断 | 步骤 5 分析的灵魂 |
| 沟通协调 | 讲得明白、推得动 | 步骤 6 报告的闭环 |

4. 点题：**五懂越硬，AI 越帮你；五懂越虚，AI 越害你。** 这个班，练的就是五懂中间那三段——从"业务出题"到"沟通交卷"的翻译能力。

---

### 模块 1：思维工具箱 —— 2 种思维 + 3 个模型

**目的**：在进入六步之前，先把"武器"摆上桌。不讲大道理，只讲"每种东西一句话是什么、用来干什么"。

#### 两种思维

| 思维 | 一句话 | 解决什么 |
|---|---|---|
| **结构化思维** | 把含糊的问题拆开看、说清楚 | 如何**看清**问题 |
| **工程化思维** | 把想法变成能落地、能验证的步骤 | 如何**改变**现实 |

**关键一句**：结构化思维让你"看懂题"，工程化思维让你"做对题"。分析需要两种交替使用。

#### 三个模型

| 模型 | 一句话 | 产出长什么样 |
|---|---|---|
| **问题模型** | 一个理解问题的简单公式 | `贸易额 = Σ HS × 单价 × 数量` |
| **信息模型** | 数据在哪张表、什么口径 | 报关单主表 + 4 张维表的关系图 |
| **数学模型** | 把答案算出来的方法（= SQL） | 一条能跑的查询 |

**关键一句**：三个模型是接力的——先拆清楚（问题模型），再找到数（信息模型），最后算出来（数学模型）。**跳过任何一个，后面都站不住。**

---

### 模块 2：六步法全图 —— 先看终点再走路

**目的**：给一张全景图，让学员知道"我们要走哪六步"。不展开，只混个脸熟。

```
业务话 → ① 拆解 → ② 找数 → ③ 建模 → ④ 验证 → ⑤ 分析 → ⑥ 报告 → 业务结论
```

| 步骤 | 做什么 | 用什么思维 | 产出什么 |
|---|---|---|---|
| ① 拆解 | 把含糊的业务话拆成几块，拼成公式 | 结构化 | 问题模型（白纸上的公式） |
| ② 找数 | 公式里的变量，对应到哪张表哪个字段 | 结构化→工程化 | 信息模型（表关系图） |
| ③ 建模 | 在工具里拖节点，拼出能跑的查询 | 工程化 | 数学模型（可视化 SQL） |
| ④ 验证 | 行数、空值、极值、抽样回查 | 工程化 | 验证清单（对得上/对不上） |
| ⑤ 分析 | 在验证过的数据上分组、排序、算贡献 | 工程化→结构化 | 表 + 图 + 三句话 |
| ⑥ 报告 | 用汇报三步法讲回业务话 | 结构化 | 一页纸结论 |

**关键一句**：1-2-6 偏结构化（拆、找、讲），3-4-5 偏工程化（建、验、用）。两种思维交替出现，缺一不可。

---

### 模块 3：慢案例走完全程 —— "出口增长乏力"

**目的**：用出口乏力的案例，六步从头走到尾。每一步都让学员看见"进去的是业务话，出来的是什么"。

#### 步骤 1：拆解（结构化思维 → 问题模型）

**业务原话**："今年出口贸易增长乏力，得查查怎么回事。"

**三个拆解动作**：

| 问 | 答案 |
|---|---|
| 跟谁比？ | 去年同期 / 全国均值 / 兄弟关 |
| 乏力在哪？ | 国家、HS 大类、企业主体、贸易方式 |
| 为什么乏力？ | 量（单数/货值）？价（单价）？结构变了？ |

**拼出公式（问题模型）**：
```
出口贸易额 = Σ 各 HS 编码 × 单价 × 数量
同比增长率 = (本期 − 同期) ÷ 同期
乏力归因   = 量贡献 + 价贡献 + 结构贡献
```

**自检标准**：拆到"能落到一张表的一个字段"为止。

> **教学要点**：这一步不进工具，白纸写就行。强迫学员养成"先想再动手"的习惯。

#### 步骤 2：找数（结构化→工程化 → 信息模型）

把公式里的变量翻译成"数据在哪"：

| 公式变量 | 数据在哪 | 口径坑 |
|---|---|---|
| 贸易额 | 报关单 × 总价（美元） | 含运保费吗？ |
| 数量 | 报关单 × 数量 + 法定单位 | 散货/整柜怎么折？ |
| HS 编码 | 报关单 × 商品编码 | 拆到 4 位还是 8 位？ |
| 同期数据 | 历史归档表 | 编码版本换过没？ |

**产出**：一张表关系图（报关单主表 + 商品归类 + 企业备案 + 国别代码 + 历史归档）。

> **教学要点**：零基础最常犯的错——跳过这步直接建模，口径都没对齐就开始聚合。

#### 步骤 3：建模（工程化 → 数学模型 = SQL）

**核心概念**：拖拽式 SQL = 不写代码的 SQL 编辑器。每个节点 = 一段 SQL，连起来 = 一条能跑的查询。

```
[数据源：报关单] → [过滤：出口+时间窗] → [聚合：按HS分组求和]
      → [计算列：同比/贡献度] → [过滤：去噪点] → [排序：TOP 50]
```

**对照表**（让学员看见"节点 ↔ SQL"的对应关系）：

| 节点 | 等价 SQL |
|---|---|
| 数据源 | `FROM customs_declaration` |
| 过滤 | `WHERE ie_flag='E' AND decl_date BETWEEN ...` |
| 聚合 | `GROUP BY hs4 ... SUM(total_price)` |
| 计算列 | `SELECT ..., (v_c-v_y)/v_y AS yoy_pct` |

> **教学要点**：让学员先看懂对照表，再动手拖。"你拖的不是花哨的可视化，是 SQL 代码本身。"

#### 步骤 4：验证（工程化 · 可验证）

**四个验证动作**：

| 验什么 | 怎么做 | 标准 |
|---|---|---|
| 行数核对 | 跟总署月报对总数 | 工具数 = 月报数 |
| 空值检查 | HS 编码为空的占比 | < 0.5% |
| 极值检查 | 单笔 > 1 亿美元的列出来 | 确认不是录错 |
| 抽样回溯 | 抽 100 条回原系统比对 | 字段一致 |

> **教学要点**：跑出来的数先别激动，先验。"模型说有疑点，业务说没有，通常不是业务错了。"

#### 步骤 5：分析（工程化→结构化）

在验证过的数据上加挂分析节点：分组汇总 → TOP N → 同比 → 贡献度 → 图表。

**产出三件套**：一张表 + 一张图 + 三句话。

三句话示例：
- **空间拆**："下滑 60% 集中在机电产品，前 3 个 HS 大类贡献了 8 成。"
- **因果拆**："量贡献 -2.1pp、价贡献 -1.5pp——量价齐跌是主因。"
- **主体拆**："中小企业下滑 -15%，头部企业 +6%，集中度在上升。"

#### 步骤 6：报告（结构化 · 回译闭环）

**汇报三步法**——把工程化的产物翻译回业务话：

1. **拆解**："增长乏力，拆开看，三个维度……"
2. **模型**："用贸易额 = 量 × 价 × 结构一拆……"
3. **方案**："建议分三条线核实……"

**自查清单**：报告里不许出现 `SELECT / WHERE / JOIN / GROUP BY`。

> **教学要点**：业务点头了，六步才算闭环。只会念节点名，翻译链就是断的。

### 模块 4：快案例迁移 —— "昨天发生了什么？"

**目的**：学员跟着走了一遍慢案例后，用一个更日常、更轻量的问题检验能不能迁移。

**业务原话**："昨天通关数据好像有点异常，看看发生了什么。"

**快速走六步**（建议做成学员练习，而非讲师演示）：

| 步骤 | 学员要做的事 |
|---|---|
| ① 拆解 | "异常"跟谁比？哪个维度异常？量还是价？→ 拼出公式 |
| ② 找数 | 昨天的报关单在哪张表？字段口径是什么？→ 画出表关系 |
| ③ 建模 | 拖出节点链：数据源→过滤(昨天)→聚合→计算(偏差)→排序 |
| ④ 验证 | 行数对不对？空值多少？有没有极端值？ |
| ⑤ 分析 | 哪个品类/企业/国别偏差最大？→ 三句话 |
| ⑥ 报告 | 用汇报三步法讲出来 |

> **教学要点**：这个环节应该让学员自己动手，讲师只纠偏。六步法的价值不在于"看懂了"，在于"自己做了一遍"。

---

### 模块 5：避坑清单 + 回译检验

**五大常见坑**：

| # | 坑 | 怎么避 |
|---|---|---|
| 1 | 跳过拆解，直接进工具 | 白纸写不出公式就别碰工具 |
| 2 | 口径没对齐就开始聚合 | 先只拖"数据源"节点，确认字段含义 |
| 3 | 跳过验证直接给结论 | 强制挂上四个验证节点 |
| 4 | 图很漂亮但结论说不清 | 每张图强制配三句话 |
| 5 | 报告里堆 SQL 术语 | 自查：不许出现技术词 |

**回译检验三问**：
1. 能不能用一句业务话讲清六步分别做什么？
2. 能不能把任何一句业务话拆成一个公式？
3. 能不能在白板上画出汇报一页纸？

三个都能 → 你不是零基础了。

---

### 模块 6：收尾 —— 四句话带走

1. **拖拽式 SQL 不是画图工具，是不写代码的 SQL 编辑器**——你拖的是计算过程。
2. **两种思维是骨架，六步是关节，拖拽是肌肉**——三者缺一，模型就瘫。
3. **能拖不代表会分析**——会拖是手艺，会拆问题是判断。手艺决定快不快，判断决定掉不掉坑。
4. **六步闭环的标志是回译**——业务能听懂、能点头、能拍板，才算完。

## 四、一句话总结本课件的逻辑

> **用两种思维武装五懂，用三个模型做工具，六步走通一个慢案例，再快速迁移一个快案例——让零基础学员从"不会写 SQL"变成"能想清楚、拖得对、讲得回"。**
