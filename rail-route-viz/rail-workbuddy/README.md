# 厦门 / 厦门北 / 冠豸山 / 冠豸山南 — 高铁动车站点路线图

一次性快照式的站点路线可视化：以某个客运站为中心，列出该日所有正在运营的
G（高铁）/ D（动车）车次，按**始发 / 到达 / 经过**三类呈现完整走向、站点时刻与途经时长。

打开 `index.html` 即可使用（数据以 `data/app_data.js` 形式内联加载，无需起服务）。

---

## 1. 目录结构

```

├─ index.html                 可视化页面（腾讯地图 GL JS）
├─ README.md                  本文档
├─ data/
│  ├─ stations.json           车站主数据：电报码 + GCJ-02 坐标
│  ├─ train_list_raw.json     全量 G/D 车次（枚举结果）
│  ├─ candidates.json         几何剪枝后的候选车次

│  ├─ app_data.json           前端数据集（JSON 版，便于二次使用）
│  └─ app_data.js             前端数据集（JS 版，页面实际加载）

└─ etl/

   ├─ 03_build_candidates.py  P2.5 坐标修正 + 几何剪枝
   ├─ 04_fetch_schedules.py   P3 逐车次抓时刻表（最耗时）
   └─ 05_build_dataset.py     P4/P5 派生计算 + 生成前端数据
```

## 2. 数据管线

| 阶段 | 脚本 | 数据源 | 说明 |
|---|---|---|---|
| P1 车站 | `01` | `kyfw.12306.cn/otn/resources/js/framework/station_name.js` + 坐标快照 | 得到 3388 站的「站名 → 电报码」，合并 GCJ-02 坐标 |
| P2 车次枚举 | `02` | `search.12306.cn/search/v1/train/search` | 按车次号前缀 BFS 递归，单次返回 ≥200 视为截断并细分一层。全量枚举只需约 160 次请求 |
| P2.5 剪枝 | `03` | — | 用车次起终点连线与目标站的几何距离剪枝，把 7000+ 车次降到可执行规模 |
| P3 时刻表 | `04` | `kyfw.12306.cn/otn/czxx/queryByTrainNo` | 逐车次拉全部经停站与到发时刻，分批落盘支持断点续传 |
| P4/P5 产出 | `05` | — | 跨天数校正、区间/累计耗时、直线距离累加，输出前端数据 |

**为什么必须先枚举再剪枝**：12306 只有「站到站」查询，没有「按站查所有车次」的开放接口。
不做全量枚举就无法保证找全经过某站的车次。

## 3. 更新数据

Python 依赖只有 `requests`。使用受管环境时：

```bash
PY=/Users/zhuangnd/.workbuddy/binaries/python/envs/default/bin/python
cd rail-workbuddy
```

### 3.1 常规刷新（换一个日期）

```bash
rm -f data/schedules_raw.json     # 关键：不清空会走断点续传，沿用旧日期的数据
RAIL_DATE=2026-10-08 $PY etl/02_fetch_train_list.py
RAIL_DATE=2026-10-08 $PY etl/03_build_candidates.py
RAIL_DATE=2026-10-08 $PY etl/04_fetch_schedules.py
RAIL_DATE=2026-10-08 $PY etl/05_build_dataset.py
```

- `RAIL_DATE` 默认 `2026-09-22`。**必须四个脚本用同一个日期**，否则车次列表与时刻表对不上。
- 日期需在 12306 预售期内（通常 15 天），超出会返回空。
- `04` 耗时最长（数千次请求，约 20~30 分钟），建议后台运行。

### 3.2 只更新车站主数据

车站电报码偶尔会因新线开通而增加：

```bash
rm -f raw/station_name.js
$PY etl/01_fetch_stations.py
```

### 3.3 调整剪枝范围

剪枝阈值默认 600 km，用环境变量覆盖（调大更保守、候选更多）：

```bash
RAIL_PRUNE_KM=900 $PY etl/03_build_candidates.py
```

## 4. 已知限制

| 项 | 说明 |
|---|---|
| 运行图差异 | 数据只反映 `RAIL_DATE` 当天。周末线、高峰线在其它日期可能不开行或时刻不同；需要完整覆盖请对多个日期分别采集后对比 |
| 直线连线 | 相邻站之间画直线，表示**站点拓扑走向**，不是铁路真实线位。跨海、绕山的大区间尤其失真 |
| 累计距离 | `cum_km` 是相邻站直线距离累加，**不是运营里程**，实际里程通常长 8%~25%。页面与数据里都标注了 |
| 坐标时效 | `raw/station_geo_gcj02.json` 是 2022 年前的社区快照，缺 782 个站（多为近年新站，如北京朝阳、重庆东、南昌东） |
| 更名错位 | 站名更名会让老坐标对不上新站名，见下节 |
| 一天一车次 | 同一车次号在不同日期可能对应不同 `train_no`（不同运行图），按 `train_no` 去重而非车次号 |

### 4.1 坐标补录

缺失坐标的站点会在线路上被跳过。补录位置是 `etl/03_build_candidates.py` 顶部的
`MANUAL_FIX` 字典，用 GCJ-02 坐标（经度在前）：

```python
MANUAL_FIX = {
    "GPS": (116.722755, 25.740146, "manual_verified"),
    "GSS": (116.680051, 25.524282, "manual_verified"),
}
```

改完重跑 `03 → 04 → 05`（`04` 会断点续传，只补新出现的车次）。

### 4.2 冠豸山 / 冠豸山南 的更名坑（务必注意）

这两个站 2021 年互换过名字，老坐标数据集极易错位：

| 现站名 | 电报码 | 位置 | 历史 |
|---|---|---|---|
| 冠豸山南 | GSS | 连城县**朋口镇**，116.6801 / 25.5243 | 原名「冠豸山站」，2021-07-01 改名 |
| 冠豸山 | GPS | 连城县**隔川镇**，116.7228 / 25.7401 | 原名「冠豸山北站」，2021-09-30 启用 |

坐标数据集里的「冠豸山」条目实际是**朋口镇的旧冠豸山站**（今天的冠豸山南），
直接套用会让冠豸山站错位约 24 km。已在 `MANUAL_FIX` 中修正，不要删除。

## 5. 采集纪律

- 并发 ≤ 3，每请求随机延迟 0.35~0.8 s；失败指数退避重试。
- 只取公开时刻表，不碰余票、票价与任何实名/账户数据。
- 页面显著位置标注数据来源与采集日期，仅供个人学习研究，不做商业分发。
- 脚本是单租户自用的一次性快照，不要改成对外服务或高频轮询。

## 6. 地图合规

底图使用**腾讯地图 GL JS**（具备国内测绘资质）。禁止替换为 Leaflet + OpenStreetMap、
Mapbox、Google / Apple / Bing 海外版等未持牌来源。页面不自行绘制任何国界、
行政区划边界数据；站点坐标为 GCJ-02，与底图一致。
